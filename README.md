工具调用与记忆系统——Agent的“手脚”和“大脑”
Agent Loop解决了“怎么循环”的问题，但循环中Agent需要两样东西才能真正工作：调用外部工具的能力（手脚）和记住历史信息的能力（记忆）。这两个模块的设计质量，直接决定了Agent是“玩具”还是“工具”。

工具系统的核心是注册与校验。 工具注册表需要做三件事：记录工具的名称和描述、定义参数的JSON Schema、维护工具名到执行函数的映射。当模型返回一个工具调用请求时，Agent需要先校验参数是否符合Schema、检查工具是否存在、然后执行并捕获异常。agent-lab项目采用注解驱动的方式——通过读取函数的签名和类型注解自动生成JSON Schema，声明永不漂移。这种设计消除了手动维护Schema与函数实现不一致的常见bug，是工具系统可靠性的基础。

异常回注是工具调用鲁棒性的关键设计。 当工具执行失败时，错误的处理方式决定了Agent是否具备自我纠正能力。简单的做法是直接抛出异常终止循环，但更优的设计是将失败转成观察结果交回模型——模型看到“除零错误”的信息后，可以自动调整参数重新调用。agent-lab的评测结果显示，在“除零失败后自我纠正”任务中，Agent通过异常回注机制在3步内完成了自我修复，全部6类任务通过率达到100%。这意味着工具系统不仅要“能调用”，还要“能容错”。

记忆系统的短期与长期之分。 对话状态、任务上下文和情节历史需要以短期和长期两种格式保存。短期记忆通过会话内的令牌上下文和结构化提示链来维持，Agent将当前计划、工具调用记录、中间结果作为消息追加到对话历史中。长期记忆则需要将记忆编码为稠密向量，通过语义相似度搜索进行检索。零基础入门时，建议先从短期记忆开始——把每一轮的工具调用结果追加到消息列表中，这是最简单但最有效的记忆机制。

上下文预算管理是记忆系统的工程约束。 每次工具调用都会产生输出，如果不加控制地全部追加到消息列表中，上下文会迅速膨胀到模型的token上限。agent-lab实现了token估算、结构保全的裁剪和压缩收益防线三层机制。具体策略包括：保留最近的N轮完整记录、对中间轮次进行摘要压缩、丢弃不再相关的工具调用结果。这些策略的选择取决于任务特征——分析类任务需要保留更多历史推理链，执行类任务则可以更激进地裁剪。

工具与记忆的协同决定了Agent的能力上限。 一个好的工具系统让Agent能够触达外部世界，一个好的记忆系统让Agent能够积累经验。两者结合后，Agent才能完成“搜索资料→记录关键信息→基于记录做推理→调用工具验证推理→根据结果调整”这样的多步任务链。零基础手写时，建议先实现一个简单的工具（如计算器或时间查询），配合消息列表作为记忆，验证“调用→记录→再调用”的完整闭环跑通后再逐步扩展。
